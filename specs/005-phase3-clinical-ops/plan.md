**Branch**: `main` | **Date**: 2026-06-19 | **Spec**: [spec.md](spec.md)

## Summary

Phase 3 extends the Paws & Claws Agentic Scheduler into the full clinical operations lifecycle, adding six agentic features across backend agents, API endpoints, and frontend components. All six features reuse the established FastAPI + SQLite + Next.js stack; no new dependencies are introduced. Every agent action is visible in the Verbose Log per the Demo-First constitution principle.

**Features**: F013 (Reminders), F014 (Waitlist Backfill), F015 (Care Tracking), F016 (Prescriptions), F018 (Breed Intelligence), F019 (Capacity Forecasting)

## Build Order (Dependency-Ordered Phases)

Phases are ordered by dependency; F018 (Breed) and F019 (Forecast) are mostly independent and can be interspersed, but F013 must precede F014 (reschedule → backfill trigger), and F015 precedes F016 (care data informs Rx context).

| Phase | Feature | Reason for order |
|---|---|---|
| Phase 1 | Schema + Models (all features) | All subsequent phases depend on tables existing |
| Phase 2 | Seed Data (all features) | Agents need data; overdue items must exist at startup |
| Phase 3 | F013 — Reminder Agent | Foundational for F014 reschedule→backfill trigger |
| Phase 4 | F014 — Waitlist Backfill | Depends on cancellation flow from F013 |
| Phase 5 | F018 — Breed Intelligence | Independent; pure lookup against breed_protocols |
| Phase 6 | F015 — Care Tracking | Independent; needed before F016 for care context |
| Phase 7 | F016 — Prescription Management | Builds on care data; refill logic uses last_exam |
| Phase 8 | F019 — Capacity Forecasting | Independent; uses existing timeblocks + new history table |
| Phase 9 | Polish + Git | Cross-cutting, backward compat validation, commit |

## Detailed Design

### Phase 1 — Schema & Models

**`backend/repository.py`** — add to `_init_db()`:

```sql
CREATE TABLE IF NOT EXISTS breed_protocols (
    id TEXT PRIMARY KEY,
    breed_pattern TEXT NOT NULL,
    flag_type TEXT NOT NULL,
    title TEXT NOT NULL,
    detail TEXT NOT NULL,
    age_threshold_years REAL DEFAULT 0,
    severity TEXT DEFAULT 'info'
);
CREATE TABLE IF NOT EXISTS waitlist (
    id TEXT PRIMARY KEY,
    patient_id TEXT NOT NULL,
    clinic_id TEXT NOT NULL,
    procedure_type TEXT NOT NULL,
    preferred_vet_id TEXT,
    urgency TEXT DEFAULT 'flexible',
    offer_status TEXT DEFAULT 'waiting',
    join_date TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS care_protocols (
    id TEXT PRIMARY KEY,
    species TEXT NOT NULL,
    protocol_name TEXT NOT NULL,
    interval_months INTEGER NOT NULL
);
CREATE TABLE IF NOT EXISTS care_events (
    id TEXT PRIMARY KEY,
    patient_id TEXT NOT NULL,
    protocol_id TEXT NOT NULL,
    timeblock_id TEXT,
    administered_date TEXT NOT NULL,
    next_due_date TEXT NOT NULL,
    batch_number TEXT DEFAULT '',
    administered_by TEXT DEFAULT ''
);
CREATE TABLE IF NOT EXISTS prescriptions (
    id TEXT PRIMARY KEY,
    patient_id TEXT NOT NULL,
    timeblock_id TEXT,
    drug_name TEXT NOT NULL,
    dose TEXT NOT NULL,
    frequency TEXT NOT NULL,
    duration_days INTEGER NOT NULL,
    refills_remaining INTEGER DEFAULT 0,
    supply_ends_at TEXT NOT NULL,
    issued_by TEXT NOT NULL,
    issued_date TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS refill_requests (
    id TEXT PRIMARY KEY,
    prescription_id TEXT NOT NULL,
    initiated_by TEXT NOT NULL,
    status TEXT DEFAULT 'pending',
    requested_at TEXT NOT NULL,
    reviewed_by TEXT,
    reviewed_at TEXT
);
```

### Phase 3 — F013 Reminder Agent

**`backend/agents/reminder.py`**:
```python
class ReminderAgent:
    def compose_message(self, patient, owner, vet, appt_time) -> str
    def process_reply(self, timeblock_id, reply: str) -> dict
        # reply in ['yes','confirm','ok'] → confirmed
        # reply in ['reschedule','cancel','no'] → reschedule_requested
    def log_steps(self, timeblock_id, action)  # → VerboseLog
```

**New endpoints in `backend/main.py`**:
- `POST /api/timeblocks/{id}/reminder/send` → sets `reminder_sent_at`, returns composed message

- `GET /api/timeblocks/action-queue` → returns `[timeblock]` where status in `[unconfirmed, reschedule_requested]`

**Frontend `AppointmentCard.tsx`**:

### Phase 4 — F014 Waitlist Backfill

**`backend/agents/backfill.py`**:
```python
class BackfillAgent:
    def score_match(self, slot: TimeBlock, entry: WaitlistEntry) -> int
        # exact procedure + vet = 100, same procedure = 80, same category = 40
        # tiebreaker: urgency desc → join_date asc
    def find_matches(self, slot: TimeBlock) -> list[ScoredMatch]
    def make_offer(self, match) -> dict
```

**New endpoints**:
- `POST /api/timeblocks/{id}/cancel` → cancels slot, triggers `BackfillAgent.find_matches()`, returns matches + log
- `GET /api/waitlist` → list all active entries
- `POST /api/waitlist` → add entry
- `POST /api/waitlist/{id}/accept` → book slot, remove from waitlist
- `POST /api/waitlist/{id}/decline` → offer_status = expired, try next match

**Frontend**:
- Cancel button on `AppointmentCard` (Front Desk) → confirmation → `WaitlistPanel` shows match + offer
- New `WaitlistPanel.tsx`: match details, score, [Accept][Decline] buttons
- Waitlist count badge in Front Desk header
